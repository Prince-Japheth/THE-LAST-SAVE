# One-Mac demonstration

1. Open `/proof`. Select one block and run the resurrection. Show the damaged image beside the verified reconstruction and matching original/output SHA-256. Download and inspect the evidence ZIP.
2. Select a second block in the same stripe. Run again. Show the explicit refusal and absence of reconstructed output. Check “Remove the final block entirely instead” and demonstrate exact tail reconstruction.
3. Open `/`. Insert MIRA’s fictional disk. Select the PCX, DBF and letter; inspect source bytes and reports. Export a recovery bundle. The story is fictional; binary parsing and exports are real.
4. Open `/preserve`. Audit the sample collection, search “Mira”, inspect conversion warnings and export inventory CSV/JSON. Export the full collection bundle. Reload to show that the desk persists separately from the archive.
5. In Kiro, open the repository root and use the evidence MCP: request the BMP contract, run reconstruction_proof with blocks [3], then [2,5]. The local protocol smoke test is `npm run test:mcp`; use `npm test` for the full suite.

Keep the demonstration under the organizer’s published video limit. A concise three-minute draft can spend 30 seconds on visible recovery, 40 on practical collection use, 60 on an actual Kiro workflow and 50 on evidence, limits and closing. This is a rehearsal structure, not a confirmed current-year requirement.

## Claims to demonstrate accurately

Prior parity enables bounded exact repair; it does not recover arbitrary missing information. Image carving finds contiguous candidates, not filesystem deletion status. Physical hardware recovery and live push delivery require separate real-device verification. Hash consistency is not historical authenticity.

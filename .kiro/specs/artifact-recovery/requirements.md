# Artifact recovery requirements

- WHEN a supported artifact is opened, THE SYSTEM SHALL deterministically decode existing bytes and report unsupported or corrupt structures.
- THE SYSTEM SHALL preserve originals and include them with modern outputs and SHA-256 manifest in recovery bundles.
- WHEN ZIP media is opened, THE SYSTEM SHALL validate headers, paths, CRCs, counts and expanded sizes before accepting extracted artifacts.
- THE SYSTEM SHALL perform decompression and parsing in workers with explicit time/memory bounds.
- THE SYSTEM SHALL support a complete one-Mac demo, keyboard controls, reduced motion and responsive layout.
- THE SYSTEM SHALL label the MIRA narrative fictional and never imply data was invented; distinguish ordinary decoding from parity-verified reconstruction and carved candidates.

- THE SYSTEM SHALL persist original bytes, provenance, selection, tab and sound preferences in IndexedDB and report storage failures. Forget session shall clear saved artifacts in that browser.
- THE SYSTEM SHALL default sound on while respecting browser interaction requirements and saved preferences.
- THE SYSTEM SHALL bound parity/carving workers to 30 seconds, require earlier redundancy for exact reconstruction, and retain damaged input separately.
- THE SYSTEM SHALL disclose 64 MiB carving input and external-disk prefix limits, supported contiguous image subsets, and unknown deletion status.
- THE SYSTEM SHALL keep files local when using optional Vercel VAPID functions, request notification permission by user action, support opt-out, and distinguish push-provider acceptance from actual delivery. No database is required.
